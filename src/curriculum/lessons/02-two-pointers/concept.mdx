# Two Pointers

Two pointers means using two indexes with specific roles. The technique is useful when a single scan can prove that parts of the input are no longer useful.

The most common versions are:

- Opposing pointers: one pointer starts at the left edge and one starts at the right edge.
- Same-direction pointers: one pointer reads each item while another records the next useful position.
- Paired scans: two arrays or strings are scanned together.

This lesson focuses on the first two because they cover most interview-style two-pointer problems.

## Opposing pointers

Opposing pointers are a good fit when the input is sorted or when the answer depends on both ends of a range.

Example prompt: Given a sorted ascending array and a target, return whether two different indexes contain values that add up to the target.

For sorted pair search, the invariant is: any pair that can still reach the target must live inside the current `[left, right]` window.

Example input: `nums = [1, 2, 4, 6, 10]`, `target = 8`.

```ts
export function hasPairWithSum(nums: number[], target: number): boolean {
  // Start with every pair still possible.
  let left = 0
  let right = nums.length - 1

  while (left < right) {
    // Test the smallest and largest remaining values together.
    const sum = nums[left] + nums[right]

    // If this pair reaches the target, the search is done.
    if (sum === target) {
      return true
    }

    if (sum < target) {
      // The left value is too small to pair with this right value or anything smaller.
      left += 1
    } else {
      // The right value is too large to pair with this left value or anything larger.
      right -= 1
    }
  }

  // No remaining pair can reach the target.
  return false
}
```

Example output: `true`.

The movement rule preserves the invariant:

- If the sum is too small, `nums[left]` cannot pair with `nums[right]` or any smaller value to reach the target, so moving `left` is safe.
- If the sum is too large, `nums[right]` cannot pair with `nums[left]` or any larger value to reach the target, so moving `right` is safe.

The sorted input is what makes those claims true. Without sorted order, moving a pointer would skip values without proof.

## Same-direction pointers

Same-direction pointers are useful when one pointer must inspect every item, but only some items should be written to the result.

Example prompt: Given a sorted ascending array, return a new array containing each distinct value once, in order.

For deduplicating a sorted array, the invariant is: `deduped.slice(0, write)` contains exactly the unique values found so far, in order.

Example input: `nums = [1, 1, 2, 2, 3]`.

```ts
export function dedupeSorted(nums: number[]): number[] {
  // There is no first value to start the result.
  if (nums.length === 0) {
    return []
  }

  // Work on a copy so the original input is not mutated.
  const deduped = [...nums]

  // The first value is already the first unique output value.
  let write = 1

  for (let read = 1; read < nums.length; read += 1) {
    // In a sorted array, a new value starts when it differs from the previous one.
    if (nums[read] !== nums[read - 1]) {
      // Place this new value at the next output position.
      deduped[write] = nums[read]
      write += 1
    }
  }

  // Return only the prefix that was written with unique values.
  return deduped.slice(0, write)
}
```

Example output: `[1, 2, 3]`.

Here `read` always advances because every value must be inspected. `write` only advances when a new unique value is found.

## Choosing the movement rule

Before writing the loop, name the evidence that justifies each pointer move.

- Pair sum in a sorted array: the current sum is too small or too large.
- Deduping sorted values: the current value is equal to or different from the previous value.
- Container with most water: the shorter wall limits the current area, so moving the taller wall cannot improve the answer while the shorter wall remains.

The movement rule should be something you can defend without saying "try the next one." It should explain what candidates were eliminated and why.

## Common mistakes

- Using opposing pointers when the input is not sorted and no other ordering rule exists.
- Moving both pointers after a failed check and skipping possible candidates.
- Using `left <= right` when the two pointers must refer to different items.
- Forgetting to handle empty arrays before reading `nums[0]`.
- Mutating an input array when the prompt asks for a returned copy.
- Returning a non-deterministic answer when multiple pairs could be valid.
