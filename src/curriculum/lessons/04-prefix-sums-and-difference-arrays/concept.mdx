# Prefix Sums and Difference Arrays

Prefix sums turn repeated range work into subtraction. Difference arrays turn repeated range updates into boundary markers. They are inverse ideas: a prefix sum accumulates values, while a difference array records where accumulated values change.

The shared question is: can you preprocess the input or delay the updates so each range does not need its own full scan?

## Prefix sums for repeated range queries

Example prompt: Given an array of numbers and many inclusive range queries `[left, right]`, return the sum inside each range.

If the array does not change between queries, build one prefix array. Use an extra leading zero with this meaning:

> `prefix[i]` is the sum of every value before index `i`.

For `nums = [3, -2, 5, 1]`, the representation is:

```ts
const nums = [3, -2, 5, 1]
const prefix = [0, 3, 1, 6, 7]
```

The leading zero makes every inclusive range use the same formula:

`rangeSum(left, right) = prefix[right + 1] - prefix[left]`

Example input: `nums = [3, -2, 5, 1]`, `left = 1`, `right = 3`.

```ts
export function rangeSum(
  nums: number[],
  left: number,
  right: number,
): number {
  // prefix[i] is the sum of values before index i.
  const prefix = new Array<number>(nums.length + 1).fill(0)

  for (let index = 0; index < nums.length; index += 1) {
    // Extend the cumulative sum by one input value.
    prefix[index + 1] = prefix[index] + nums[index]
  }

  // Subtract the values before left from the sum through right.
  return prefix[right + 1] - prefix[left]
}
```

Example output: `4`, because `-2 + 5 + 1 = 4`.

Building the prefix array costs O(n). Each query then costs O(1). This tradeoff is useful when there are enough queries to justify O(n) preprocessing and the source array stays unchanged.

## Counting subarrays by prefix value

A prefix array answers a known range. A prefix-sum frequency map can count ranges whose starting index is unknown.

Example prompt: Given an array that may include negative values, count the contiguous subarrays whose sum equals `target`.

Suppose the prefix through the current index is `currentPrefix`. If an earlier prefix equals `currentPrefix - target`, the values between those two prefixes sum to `target`:

`currentPrefix - earlierPrefix = target`, so `earlierPrefix = currentPrefix - target`.

Example input: `nums = [1, -1, 0]`, `target = 0`.

```ts
export function countTargetSumSubarrays(
  nums: number[],
  target: number,
): number {
  // The empty prefix has sum zero and ends before the array starts.
  const frequencies = new Map<number, number>([[0, 1]])
  let currentPrefix = 0
  let count = 0

  for (const num of nums) {
    // Extend the prefix through the current value.
    currentPrefix += num

    // Every matching earlier prefix creates one subarray ending here.
    const requiredPrefix = currentPrefix - target
    count += frequencies.get(requiredPrefix) ?? 0

    // Record this prefix after counting so a subarray is never empty.
    frequencies.set(
      currentPrefix,
      (frequencies.get(currentPrefix) ?? 0) + 1,
    )
  }

  return count
}
```

Example output: `3`, for `[1, -1]`, `[1, -1, 0]`, and `[0]`.

The initial frequency `0 -> 1` represents the empty prefix. It allows a subarray starting at index zero to be counted. Frequencies, rather than a `Set`, are required because the same prefix value may occur several times and each occurrence creates a different subarray.

This technique works with negative values because it does not assume the sum moves in one direction. A standard grow-and-shrink sliding window usually cannot make that guarantee when values may be negative.

## Difference arrays for batched range updates

Example prompt: Start with an array of zeroes. Apply many updates that add `delta` to every index in an inclusive range `[start, end]`, then return the final array.

Updating every covered index can cost O(n) per update. A difference array records only the two boundaries where an update changes the running value:

- Add `delta` at `start`.
- Subtract `delta` at `end + 1`.
- Take one prefix sum after all updates to reconstruct the result.

For a length-5 array and the update `[1, 3, 2]`, the difference markers are:

```ts
const difference = [0, 2, 0, 0, -2, 0]
const result = [0, 2, 2, 2, 0]
```

The `2` begins at index `1`. The `-2` at index `4`, which is `end + 1`, stops that addition before index `4` enters the result. The extra difference slot lets an update ending at the final output index place its stop marker safely.

Example input: `length = 5`, `updates = [[1, 3, 2], [2, 4, 3], [0, 2, -2]]`.

```ts
export function applyRangeUpdates(
  length: number,
  updates: [number, number, number][],
): number[] {
  // The extra slot can hold a stop marker after the last output index.
  const difference = new Array<number>(length + 1).fill(0)

  for (const [start, end, delta] of updates) {
    // Start applying delta at the inclusive left boundary.
    difference[start] += delta

    // Stop applying delta immediately after the inclusive right boundary.
    difference[end + 1] -= delta
  }

  const result = new Array<number>(length).fill(0)
  let running = 0

  for (let index = 0; index < length; index += 1) {
    // Integrate the markers to recover the value at this index.
    running += difference[index]
    result[index] = running
  }

  return result
}
```

Example output: `[-2, 0, 3, 5, 3]`.

Difference arrays are a fit when updates can be collected before the final values are needed. They are not a complete replacement for a data structure that must support interleaved online updates and queries.

## Choosing the pattern

- Many range queries over unchanged values: build a prefix array.
- Count subarrays with a target sum, especially with negative values: store prefix frequencies.
- Maintain one moving contiguous range under a safe movement rule: use a sliding window.
- Apply many range updates, then read the final values: build a difference array and integrate once.

State whether endpoints are inclusive or exclusive before writing the formula. This lesson uses inclusive `left`, `right`, `start`, and `end` indexes.

## Common mistakes

- Building a prefix array of length `n` and adding a special case for ranges that start at zero.
- Using `prefix[right] - prefix[left]` for an inclusive query instead of `prefix[right + 1] - prefix[left]`.
- Forgetting to seed the prefix frequency map with `0 -> 1`.
- Recording the current prefix before counting matches, which can count an empty subarray when `target` is zero.
- Using a `Set` when repeated prefix values should create multiple valid subarrays.
- Subtracting a difference update at `end` instead of after the inclusive end.
- Using prefix sums as if the source array were still unchanged after online mutations.
