# Dynamic Programming Fundamentals

Dynamic programming stores answers to smaller subproblems so repeated work can reuse them. It applies when a problem can be described using smaller versions of the same problem and many possible routes ask for the same smaller result.

Before writing code, define what one stored state means. Then identify its base case, how earlier states produce the current state, and the order that makes those earlier states available.

## Combine a fixed number of earlier states

Example prompt: Count the move sequences that climb a staircase when every move is one or two steps.

Let `ways[i]` mean the number of sequences that reach step `i`. Every final move comes from step `i - 1` or `i - 2`, so `ways[i] = ways[i - 1] + ways[i - 2]`.

Example input: `stepCount = 5`.

```ts
export function countClimbingWays(stepCount: number): number {
  if (stepCount <= 1) {
    return 1
  }

  let twoStepsBack = 1
  let oneStepBack = 1

  for (let step = 2; step <= stepCount; step += 1) {
    // Every route here arrives from one or two steps below.
    const currentWays = oneStepBack + twoStepsBack
    twoStepsBack = oneStepBack
    oneStepBack = currentWays
  }

  return oneStepBack
}
```

Example output: `8`.

Only the previous two counts are needed, so the complete `ways` array can be replaced by two variables.

## Represent a choice with take and skip results

Example prompt: Return the largest sum made from values that are not next to each other.

At each index, compare two complete possibilities:

- Skip the current value and keep the best result through the previous index.
- Take the current value and add it to the best result through two indexes earlier.

Example input: `values = [2, 7, 9, 3, 1]`.

```ts
export function maximumNonAdjacentSum(values: number[]): number {
  let bestTwoIndexesBack = 0
  let bestOneIndexBack = 0

  for (const value of values) {
    const takeCurrent = bestTwoIndexesBack + value
    const skipCurrent = bestOneIndexBack
    const currentBest = Math.max(takeCurrent, skipCurrent)

    bestTwoIndexesBack = bestOneIndexBack
    bestOneIndexBack = currentBest
  }

  return bestOneIndexBack
}
```

Example output: `12`.

The state stores the best valid sum, not the values selected to create it. If the selected indexes were also required, retain enough information to reconstruct those choices.

## Build results for every smaller amount

Example prompt: Return the fewest reusable coins needed to form an amount, or `-1` when it cannot be formed.

Let `minimumCoins[a]` be the fewest coins needed for amount `a`. Start with `minimumCoins[0] = 0`. For each later amount, try adding one coin to a smaller amount that has already been calculated.

Example input: `coins = [1, 3, 4]`, `amount = 6`.

```ts
export function minimumCoinsForAmount(
  coins: number[],
  amount: number,
): number {
  const minimumCoins = Array<number>(amount + 1).fill(Infinity)
  minimumCoins[0] = 0

  for (let currentAmount = 1; currentAmount <= amount; currentAmount += 1) {
    for (const coin of coins) {
      if (coin <= currentAmount) {
        minimumCoins[currentAmount] = Math.min(
          minimumCoins[currentAmount],
          minimumCoins[currentAmount - coin] + 1,
        )
      }
    }
  }

  return minimumCoins[amount] === Infinity ? -1 : minimumCoins[amount]
}
```

Example output: `2`.

`Infinity` means an amount has not been reached. Adding one to `Infinity` remains `Infinity`, so unreachable smaller amounts cannot create a false finite result.

## Memoization and tabulation

Memoization starts with a recursive definition and stores each result the first time it is requested. Tabulation starts with base cases and fills states in an explicit order. Both are dynamic programming when they calculate each required state once and reuse it.

Choose the form that makes the state and dependency order easiest to verify. Iterative tabulation also avoids JavaScript call-stack limits.

## Common mistakes

- Writing code before defining what one state means.
- Omitting a base case for zero or an empty input.
- Reading a state before it has been calculated.
- Using a greedy choice when the best current option can block a better combination.
- Recalculating the same recursive state without memoization.
- Compressing storage before the dependency relationship is correct.
- Returning `Infinity` instead of the prompt's required missing-result value.
- Claiming O(1) space while retaining a table proportional to the input.
